# Исследование: референс Яндекс Погода, источники данных, стек

Дата: 25.10.2026 · Материалы: `.reference/` (6 скриншотов, скринкаст, 2 HAR, APK), `.analysis/` (скрипты и выгрузки).

## 1. Функциональная карта референса

Восстановлена по скриншотам, кадрам видео и декодированному манифесту APK.

**Главный экран**
- Шапка: город + район («Москва / район Отрадное»), меню (гамбургер, список городов), настройки.
- Текущая погода: крупная температура, иконка, текст состояния, «Ощущается как».
- Метрики слева: ветер (скорость + направление + стрелка), давление (мм рт. ст.), влажность, температура воды (для прибрежных городов).
- Почасовая лента: «сейчас» + часы, иконки день/ночь, температуры; горизонтальный скролл минимум на 2 суток (в видео прокрутка до 07:00 следующих суток).
- Карточка-карта с баннером осадков («В ближайшие 2 часа осадков не ожидается»), карусель из 3 карточек (индикатор-точки).
- «Прогноз на 10 дней»: список (дата, день недели, иконка, днём/ночью); выходные подсвечены.
- Ниже: раздел «Погода на карте», кнопка «Показать на карте», кнопка «Прогноз на месяц», блок Meteum.

**Экран «Погода на карте»**
- Полноэкранный тайловый рендер, селектор слоя (в HAR: осадки, температура, ветер, давление, снег — `/frontend/raster-maps/{layer}/raw-tile`).
- Таймлайн −2 ч … +2 ч с меткой «Сейчас», скраб и проигрывание анимации.
- Пин города; плашка краудсорсинга «У вас идет дождь? Да / Нет».

**Настройки**
- Единицы: °C/°F, м/с | км/ч, мм рт. ст. | гПа.
- Тема: светлая / тёмная / как в системе.
- Геолокация (тумблер, «прогноз станет точнее»), «Место»: текущее / выбор.
- Настройки виджетов: на главном экране; на главном экране с картой осадков; на панели уведомлений.
- Раздел «Уведомления».

**Виджеты (по манифесту, 5 провайдеров)**
- Горизонтальный («часы + погода»), новый горизонтальный, малый, большой, часы; у каждого свой Setup-активити; фон/прозрачность/ч-б иконки настраиваются; обновление через `WeatherWidgetService`/`WeatherWidgetJobService`.

**Уведомления (скриншот 6)**
- Погодное уведомление «Погода на сегодня · Москва: +5…+11°, Ясно, без осадков, слабый ветер 3–4 м/с, порывы до 9 м/с».
- Виджет в шторке: иконка + температура + «Ощущается как» + ветер + город.

## 2. Реверс APK (ru.yandex.weatherplugin 24.5.2)

`minSdk 23`, `targetSdk 34`, `versionCode 240050002`. Инструменты: распаковка zip + собственный парсер AXML/DEX (jadx/apktool в окружении нет, ничего не устанавливалось).

**Размер (compressed / uncompressed):**
| Группа | Размер |
|---|---|
| Всего | 32.1 МБ / 56.1 МБ |
| classes*.dex (3 файла) | 10.9 МБ / 29.0 МБ, **181 988 методов** |
| res/drawable (5623 файла) | 9.55 МБ |
| resources.arsc | 3.78 МБ / 4.38 МБ |
| Шрифты (res/font + assets/fonts, 32 файла) | 1.8 МБ / 4.5 МБ |
| lib/ — 4 ABI (arm64-v8a, armeabi-v7a, x86, x86_64) | 4.1 МБ |
| res/layout (549), прочие res | 0.9 МБ |

**Стек из DEX (число типов по префиксам):** com/yandex 15 605, com/google 4 233, ru/yandex 3 745, io/appmetrica 2 717, kotlin/reflect 1 742, androidx: core 1 249, appcompat 525, datastore 469, work 436, constraintlayout 377, recyclerview 265, lifecycle 261, room 238; kotlinx-serialization 362, apollographql 236, lottie (com/airbnb) 212, kryo 196, okhttp, slf4j/logback 457, simplexml 387.

Выводы:
1. **UI — классические Views** (549 layout-файлов, AppCompat/ConstraintLayout/RecyclerView). Jetpack Compose в APK нет — даже Яндекс для этого приложения не счёл его нужным.
2. **Карт — нет MapKit**: карта рендерится из векторных тайлов `core-renderer-tiles.maps.yandex.net/vmap3` (свой рендер + частью в WebView: в assets лежит React 17 бандл).
3. ~80 % размера — коммерческая обвязка (реклама adfox/метрика, паспорт/SSO, AppMetrica, Crashlytics, 4 ABI, 3 dex из-за 182k методов, дублированные шрифты). Функциональному минимуму из раздела 1 соответствует **оценка 2.5–3.5 МБ APK** — это и есть наш ориентир.

## 3. Источник №1: pogoda.yandex.ru / api.weather.yandex.ru

Из HAR (191 запрос):
- **`POST api.weather.yandex.ru/graphql/query`** — главный API. В перехвате — запросы `nowcastReports` (краудсорс-«зонтики») и `thunders` (громы): GraphQL-запрос в JSON-теле, **без cookie и Authorization** (заголовки запроса: только стандартные браузерные). CORS ограничивает браузеры, но нативному клиенту эндпоинт доступен напрямую — проверить спайком (UA/origin-заголовки).
- **`GET /frontend/nowcast/new_encoded_tile`** — бинарные тайлы осадков (баннер «2 часа»).
- **`GET /frontend/raster-maps/{temperature|union-wind|pressure-mm|snow-depth}/raw-tile`** — тайлы слоёв карты.
- Данные страниц идут как **`text/x-component`** (React Server Components, Next.js): 14 ответов по 70–260 КБ. Парсить неудобно — запасной вариант, не основной.
- Тайлы базовой карты: `core-renderer-tiles.maps.yandex.net/vmap3/tiles` (вектор) + `style`, глифы.

Официальное положение: API Яндекс Погоды — тот же эндпоинт `api.weather.yandex.ru/graphql/query`, но **платный B2B**: 7 дней бесплатно, далее от 540 000 ₽/год за 100 000 запросов/мес ([yandex.ru/dev/weather, тарифы](https://yandex.ru/dev/weather/doc/ru/concepts/pricing)); бесплатный доступ — только интеграция умного дома на 2 дня ([Habr, 2024](https://habr.com/ru/companies/yandex/news/842738)). Использование веб-эндпоинта без ключа — не задокументировано и может меняться: риск №1, закрывается кэшированием и деградацией на источник №2.

## 4. Источник №2: meteored.com

Из HAR (825 запросов, все — только картографические сервисы `services-{a,b,c}.meteored.com`):
- `GET /web/tiles/viewer/v2/radar.json` — таймстампы кадров радара (прошлые + будущие), т.е. готовая радарная анимация осадков.
- `GET /web/tiles/symbols/{z}/{x}/{y}/{YYYYMMDDHH}.json` — коды символов погоды по городам внутри тайла (id города → массив кодов по часам).
- `GET /img/labels/{z}/{x}/{y}/ru.json` — подписи городов; `GET /web/maps/cep010.json` — референс прогона прогностических карт (давление).

**Прогнозного JSON API в HAR нет** — данные прогноза сайт отдаёт внутри HTML. Публичного API у Meteored нет: только B2B «Request a demo» ([meteored.com/business](https://www.meteored.com/business)); legal notice разрешает переиспользование контента с атрибуцией и ограничивает продукты ECMWF ([meteored.com/legal](https://www.meteored.com/legal)). Явного запрета на автоматический доступ в open sources не найдено, но это не «согласие».

Следствие для архитектуры: прогноз от Meteored — **парсинг HTML** (хрупкий, закрывается тестами на фикстурах) либо только картографические сервисы; радар осадков — готовый и стабильный.

## 5. Выбор стека: цифры по размеру

| Стек | Минимальный release APK | Источник |
|---|---|---|
| Kotlin + XML Views (R8 full, shrink) | **2 252 КБ** | [Google, сравнение метрик Compose/Views (Sunflower)](https://developer.android.com/develop/ui/compose/migrate/compare-metrics) |
| Kotlin + Jetpack Compose | 2 966 КБ (**+714 КБ, +32 %**) | там же |
| KMP (Android-таргет, тот же код) | 1 463 КБ | [jacobras.nl, 2023](https://www.jacobras.nl/2023/09/android-ios-native-flutter-compose-kmp) |
| Flutter | ≈ 5× нативного (≈ 7 МБ) | там же |
| React Native | 23–27 МБ universal | грубые оценки, не подтверждено свежими замерами |

Неподтверждённое (исследователь пометил): свежие (2024–2026) hello-world замеры Flutter/RN, «AAB на ~15 % меньше APK», точная экономия от отказа от AppCompat, установочные размеры из Play.

## 6. Выводы

1. **Kotlin, нативный Android** — очевидный выбор: самый компактный, полный доступ к AppWidget/Notification/LocationManager, альтернативы либо тяжелее (Flutter ×5, RN ×10), либо не дают преимуществ на одном таргете (KMP).
2. **Views, а не Compose** (+0.7 МБ экономии, у референса так же), по возможности **без androidx-зависимостей** (ListView/ScrollView + платформенные виджеты покрывают наш UI).
3. Источники: **Яндекс — основной прогноз** (GraphQL, спайк на доступность), **Meteored — радар осадков и/или HTML-прогноз**; доменная модель и репозиторий мультиисточниковые с переключением в настройках.
4. Карту делаем **своим тайловым вью** (OSM-растры + оверлеи радара), без MapKit/Maps SDK — так делает и референс (свой рендер).
5. Целевой размер: **≤ 3.5 МБ universal APK**, ≤ ~2.5 МБ install из AAB (arm64). Бюджет по компонентам — в архитектуре.

## 7. Зафиксированные решения (25.10.2026, Сергей)

1. **Скорость разработки важнее размера** — стек ускорен: Compose + Material 3, WorkManager, osmdroid; рост APK до ~5 МБ допустим.
2. **Meteored исключён**: радар дублируется возможностями Яндекса, HTML-парсинг прогноза отклонён. Остался один источник — Яндекс (резервный план Б — Open-Meteo).
3. Неймспейс/`applicationId`: **`tech.stpnk.weather`**; релизная подпись — собственный keystore (реквизиты в `local.properties`, не коммитятся).
4. Поиск городов — Open-Meteo geocoding (без ключа).

Актуальная архитектура и план — в `docs/02-architecture.md` (v2) и `docs/03-plan.md` (v2); этот документ сохранён как исследование с выводами на момент анализа.
