# Архитектура приложения «Погода» (v2 — решения от 25.10.2026 внесены)

Изменения против v1 по решениям Сергея: **скорость разработки важнее размера** (увеличение APK допустимо), **Meteored исключён** (радар дублируется возможностями Яндекса, HTML-парсинг прогноза отклонён), неймспейс `tech.stpnk.*`, релизная подпись — собственный keystore.

## 1. Цели

- Скорость разработки — приоритет; стек максимально «стандартный» и знакомый.
- Размер всё равно контролируем: ориентир **universal release APK ≤ 5 МБ** (CI-замер), жёсткого бюджета нет.
- Функционал — паритет с референсом (см. `docs/01-research.md` §1), без рекламы/аккаунтов/пуша/краудсорсинга; «Прогноз на месяц» — v2.

## 2. Язык и платформа

**Kotlin 2.0 + Jetpack Compose (Material 3), minSdk 26, targetSdk/compileSdk 35, AGP 8.7.3, Gradle 8.10.2, R8 full mode.**

- Compose выбран ради скорости разработки (+~0.7 МБ к Views по бенчмарку Google — принято).
- `namespace`/`applicationId`: **`tech.stpnk.weather`**.
- minSdk 26 (Android 8) — упрощает иконки/каналы уведомлений, покрывает ~99 % устройств.

## 3. Слои и структура (один модуль `:app`)

```
tech.stpnk.weather
├── domain/            # модели (Place, Current, HourPoint, DayForecast, Nowcast, Units) + Repository
├── data/
│   ├── yandex/        # YandexSource: GraphQL-клиент api.weather.yandex.ru/graphql/query,
│   │                  #   DTO kotlinx-serialization, nowcast/raster-тайлы
│   ├── geo/           # OpenMeteoGeocoder: поиск городов (geocoding-api.open-meteo.com, без ключа)
│   ├── cache/         # файловый JSON-кэш (filesDir, TTL по типу данных)
│   └── repo/          # WeatherRepository: Яндекс → кэш → деградация на кэш при ошибках
├── ui/
│   ├── main/          # главный экран: сейчас, почасовая лента, 10 дней, карточка осадков
│   ├── map/           # карта погоды: osmdroid + слои Яндекса, таймлайн
│   ├── settings/      # единицы, тема, место, интервал обновления
│   ├── cities/        # список/поиск городов
│   └── theme/         # тема (готова в скелете)
├── widget/            # AppWidgetProvider ×2 (RemoteViews — Compose в виджетах недоступен)
├── notify/            # «Погода на сегодня» + виджет в шторке
├── bg/                # WorkManager: периодическое обновление (constraints: сеть)
└── App.kt             # AppContainer — ручной DI (без Hilt: меньше магии и времени сборки)
```

## 4. Ключевые решения (v2)

| Область | Выбор | Комментарий |
|---|---|---|
| UI | **Compose + Material 3 + Navigation-Compose + ViewModel** | скорость; +0.7 МБ принято |
| Источник | **только Яндекс** (GraphQL + nowcast/raster-тайлы) | Meteored исключён 25.10.2026; интерфейс `WeatherSource` сохраняем — план Б (Open-Meteo как резервный прогноз) подключается без переделки UI |
| Сеть | OkHttp 4.12 | HTTP/2, надёжность |
| JSON | kotlinx-serialization 1.7 | типобезопасные DTO, много optional-полей |
| Фон | **WorkManager** periodic (30–60 мин, constraint: сеть) | проще AlarmManager в поддержке; +~0.5 МБ принято |
| Хранение | SharedPreferences + файловый JSON-кэш | без Room/DataStore — быстрее писать, данных мало |
| Геолокация | LocationManager (без Play Services) | разрешение при использовании; фолбэк — ручной город |
| Поиск городов | **Open-Meteo geocoding** (без ключа, язык ru) | третий сервис, но только для поиска; документированный и стабильный |
| Карта | **osmdroid 6.1.20** + растровые тайлы; слои Яндекса поверх | свой TileView не пишем — скорость; радар/nowcast — по итогам спайка формата тайлов |
| Виджеты | RemoteViews, обновление из WorkManager | штатно |
| DI | ручной AppContainer | без Hilt/Koin |
| Подпись | свой keystore Сергея; пути/пароли в `local.properties` (не коммитится) | до заполнения релиз подписывается debug-ключом |

## 5. Источник данных: Яндекс

- **Прогноз**: `POST api.weather.yandex.ru/graphql/query` — запросы вида `query main { … }` (шаблоны из HAR; в HAR эндпоинт вызывался без cookie/Authorization). Спайк этапа 2 фиксирует конкретные запросы (fact/hourly/daily/location) и сохраняет ответы как фикстуры тестов.
- **Баннер осадков**: бинарный тайл `/frontend/nowcast/new_encoded_tile` — спайк формата; если не расшифруем, текст баннера собирается из почасового прогноза (поля precipitation/condition).
- **Карта**: растровые слои `/frontend/raster-maps/{temperature,union-wind,pressure-mm,snow-depth}/raw-tile` — спайк формата (PNG/бинарный). Слой осадков — из nowcast-тайла или радарной анимации; при недоступности — слой откладывается, карта остаётся с базовыми тайлами OSM.
- **Риски и деградация**: эндпоинт недокументирован — код обязан жить при 403/429/изменении схемы: показ кэша, retry с backoff, понятная ошибка в UI. Если Яндекс закроет доступ — резервный план: Open-Meteo (бесплатный, без ключа) как второй `WeatherSource`.
- **Кэш**: JSON в filesDir, ключи `datatype+placeId`, TTL 30 мин (только снижает частоту запросов; показ всегда из кэша + фоновое обновление).
- Атрибуция «Данные: Яндекс Погода (Meteum)» — в настройках и внизу главного экрана.

## 6. Экраны

- **Main** (Compose): Lazy-вертикаль из блоков: шапка (город/район, меню, настройки), текущая погода + метрики, почасовая лента (LazyRow), карточка осадков, LazyColumn 10 дней, кнопка «Показать на карте».
- **Map**: osmdroid MapView, переключатель слоёв, таймлайн −2…+2 ч (кадры радара/nowcast), пин города.
- **Cities**: список + поиск (Open-Meteo), добавление/удаление; геолокация — кнопка «Моё место».
- **Settings**: единицы (°C/°F, м/с|км/ч, мм рт. ст.|гПа), тема (светлая/тёмная/системная), основной источник (зарезервировано), интервал обновления, атрибуция.

## 7. Бюджет размера (ориентир, не жёсткий лимит)

Compose-стек добавляет к v1-оценке: Compose runtime+UI ~1.5 МБ, Navigation ~0.15 МБ, WorkManager ~0.5 МБ, osmdroid ~2 МБ (сжато ~1 МБ) → ожидание **universal APK 5–7 МБ**, AAB-инсталл (arm64) ~3.5–4.5 МБ. R8 + resource shrinking обязательны; отчёт о размере — на каждом UI-этапе и в финале.

## 8. Верификация (правила проекта)

- Тесты парсеров/домена — на **фикстурах из HAR и спайков** (реальные ответы).
- Базовая линия каждого этапа: `assembleDebug`/`assembleRelease` + `testDebugUnitTest` + замер APK; новые падения не смешиваем с существующими.
- Ручная проверка на устройстве по чек-листу перед релизом.
- CI GitHub Actions: сборка + тесты на каждый push в main.
